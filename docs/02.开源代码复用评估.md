# 02. 开源代码复用评估

> 状态：用户已选择以 patrickloeber 仓库为主要代码基础、尽量少改；本评估仍只基于静态代码与许可核对，未安装依赖、运行程序或训练。工作区已有用户放入的上游副本和 ZIP，但尚未纳入 Git、修改或用于训练。02–04 的原方案需要据此修订；实际代码迁移仍须等待修订后的 [01. 技术方案](01.技术方案-待审核.md) 获审核通过。

## 判断标准

“可直接使用”分三层：**能作为原项目运行**、**能作为本课程项目的基础继续改造**、**不改动就符合指定论文与已确认方案**。这三层不能混为一谈。主论文仍是 [Mnih 等，Nature 2015](../Human-level%20control%20through%20deep%20reinforcement%20learning.pdf)；GitHub 代码提供游戏与工程基础，不自动成为论文方法的证据。

## 仓库一：patrickloeber/snake-ai-pytorch

核对版本：[上游提交 7ea69e6](https://github.com/patrickloeber/snake-ai-pytorch/tree/7ea69e6b79c59db731d8befc9ec174b075efc808)。仓库使用 [MIT 许可](https://github.com/patrickloeber/snake-ai-pytorch/blob/7ea69e6b79c59db731d8befc9ec174b075efc808/LICENSE)；复制或修改时应保留原版权与许可声明，并在本项目说明改动来源。

用户放入的 snake-ai-pytorch-main/ 目录中，agent.py、game.py、model.py、helper.py、README.md、LICENSE 和 arial.ttf 与上述上游提交逐字节一致。目录及 ZIP 目前均未跟踪；本评估没有改动它们。

| 文件与事实 | 可以沿用 | 与当前方案的差异 |
| --- | --- | --- |
| [game.py](https://github.com/patrickloeber/snake-ai-pytorch/blob/7ea69e6b79c59db731d8befc9ec174b075efc808/game.py) 提供贪吃蛇规则、随机食物、三种相对动作及 Pygame 画面 | 游戏循环和交互规则可作为直接基础 | 创建游戏时即打开窗口，规则与显示耦合；未提供受控种子、无界面运行和独立评估 |
| [agent.py](https://github.com/patrickloeber/snake-ai-pytorch/blob/7ea69e6b79c59db731d8befc9ec174b075efc808/agent.py) 使用 11 项危险/方向/食物特征、ε-greedy、逐步单样本更新和回合结束后的回放更新 | 状态提取、动作与训练循环可作为可运行基线 | 11 项局部观察没有有序蛇身，不等于完整马尔可夫状态；回放更新频率也不同于论文每步采样训练 |
| [model.py](https://github.com/patrickloeber/snake-ai-pytorch/blob/7ea69e6b79c59db731d8befc9ec174b075efc808/model.py) 使用 11→256→3 的 MLP、Adam、MSE | Q 网络和基础 TD 更新代码可沿用 | 下一状态的目标仍由同一个网络计算，没有论文式独立目标网络；更新目标需显式停止梯度；与原方案的轻量 CNN 不同 |
| [helper.py](https://github.com/patrickloeber/snake-ai-pytorch/blob/7ea69e6b79c59db731d8befc9ec174b075efc808/helper.py) 绘制训练得分 | 可用于早期可视化 | 不能代替固定种子、独立评估和多次运行的消融结果 |

**结论**：适合作为**主要代码基础**。在安装所需依赖和检查运行环境后，它有望按原方式运行；但**原样使用不足以完成本项目已确认的 DQN 机制验证**。至少需要补独立目标网络、停止目标梯度、按统一更新节奏采样回放，以及可复现评估与消融。最大程度复用时，主观察保留 11 项特征、主网络保留 MLP，并在报告中说明这是部分观察，不把它写成论文的像素 CNN。

当前本机 Python 3.10 环境没有 PyTorch、Pygame 和 IPython；上游代码分别导入这些包。本轮按约定不安装依赖，所以“有望运行”是静态判断，**不是已运行验证**。

上游还包含 arial.ttf，游戏代码直接按相对路径加载。仓库的 MIT LICENSE 明确覆盖软件，但字体文件的单独来源与再分发条件未核实；若将改造代码放入公开仓库，宜先用系统字体替代，不把该 TTF 直接上传。

## 仓库二：billodalroy/Snake-Game-Deep-Reinforcement-Learning

核对版本：[上游提交 7145e2c](https://github.com/billodalroy/Snake-Game-Deep-Reinforcement-Learning/tree/7145e2c1b0cebd4f16ef3978b296819ea86dcd8b)。仓库也使用 [MIT 许可](https://github.com/billodalroy/Snake-Game-Deep-Reinforcement-Learning/blob/7145e2c1b0cebd4f16ef3978b296819ea86dcd8b/LICENSE)。

| 文件与事实 | 直接使用的障碍 |
| --- | --- |
| [DQN notebook](https://github.com/billodalroy/Snake-Game-Deep-Reinforcement-Learning/blob/7145e2c1b0cebd4f16ef3978b296819ea86dcd8b/Snake_game_dqn.ipynb) 定义向量观察和 MLP | 没有独立目标网络；不符合指定论文 DQN 的关键机制 |
| 同一 notebook 声明四个动作，但 step 只分别处理 0、1、2 | 第四个动作会落入“未转向”的路径，动作定义与执行不一致 |
| 同一 notebook 在碰撞时先赋死亡奖励，后续又对 reward 赋距离/食物奖励 | 从代码顺序看，碰撞惩罚会被覆盖；需修正后才能作为可靠实验环境 |
| notebook 中的显示函数引用 /kaggle/input 路径下的图片 | 显示依赖特定运行环境，不能直接在本项目仓库中复用 |
| [DDQN notebook](https://github.com/billodalroy/Snake-Game-Deep-Reinforcement-Learning/blob/7145e2c1b0cebd4f16ef3978b296819ea86dcd8b/Snake_game_ddqn.ipynb) 有目标网络 | 它实现的是后续 Double DQN 变体，不能当成 2015 年主论文的基础 DQN |

**结论**：适合阅读和对照算法思路，**不推荐作为直接移植的主代码**。上述问题基于静态代码核对，尚未通过运行复现；这不影响先判断其移植成本高于第一份仓库。

## 与先前自建方案的差异

| 部分 | 已被替代的自建方案 | 当前开源复用方向 |
| --- | --- | --- |
| 02 游戏环境 | 独立、可无界面运行的网格规则 | 先沿用 Pygame 游戏，之后仅把显示设为可关闭，并补随机种子与评估接口 |
| 03 MDP 建模 | 有序蛇身网格观察、朝向与剩余步数 | 游戏内部状态仍可完整定义为 MDP；智能体先用上游 11 项局部观察，并明确它不是完整状态 |
| 04 DQN 算法 | 轻量 CNN、MSE + Adam、回放与目标网络 | 沿用上游 MLP、MSE + Adam 与回放，补独立目标网络和周期性硬同步 |
| 05 实验设计 | 随机/规则基线、回放/目标网络消融 | 方向可保留，但需新增独立评估与日志，不能只用上游训练曲线 |
| 06 工程架构 | 小型模块化工程 | 可以先保持上游脚本边界，随必要修改再分离训练/评估，无需一开始重写整个目录 |
| 07 成果展示 | 图表、课程汇报、Demo | 可沿用上游游戏画面和基础得分图，补可复核实验图表 |
