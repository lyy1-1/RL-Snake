## 依据与核心判断

- **主要理论依据**：[Mnih 等，Human-level control through deep reinforcement learning，Nature 2015](../Human-level%20control%20through%20deep%20reinforcement%20learning.pdf)。论文研究 Atari 2600，关键 DQN 机制是均匀经验回放与定期同步的独立目标网络；像素 CNN 属于其具体输入与网络设计。
- **主要工程基础**：[patrickloeber/snake-ai-pytorch，上游提交 7ea69e6](https://github.com/patrickloeber/snake-ai-pytorch/tree/7ea69e6b79c59db731d8befc9ec174b075efc808)。用户放入工作区的同名目录中，核心代码、README、许可和字体文件已与该提交逐字节核对；目录和 ZIP 尚未加入 Git。
- **补充参考**：[billodalroy/Snake-Game-Deep-Reinforcement-Learning](https://github.com/billodalroy/Snake-Game-Deep-Reinforcement-Learning)，仅用于对照阅读。其 DQN notebook 没有独立目标网络，且静态检查发现动作定义与碰撞奖励需要修正；不作为主代码基础。详情见 [02. 开源代码复用评估](02.开源代码复用评估.md)。
- **课程补充材料**：本地 PPT/4-DQN.pdf 与 PPT/5-DQN改进.pdf，用于核对课堂术语与公式，不替代主论文；这些课件未上传公开仓库。
- **决策状态**：[PROJECT_DECISIONS.md](PROJECT_DECISIONS.md) 记录已确认方向和被替代的旧方案。本方案的默认参数、源代码迁移形式及预算仍需审核。

本项目的表述应是“**基于开源贪吃蛇实现，补足并验证指定论文的 DQN 关键机制**”。不得把上游原版称为论文完整 DQN，也不得把贪吃蛇成绩称为原论文的 Atari 复现结果。

## 01｜项目定位

**原论文**：从游戏画面学习动作价值，在 Atari 上分析经验回放和目标网络等组件。**参考代码**：patrickloeber 提供教学用贪吃蛇环境、11 特征观察、MLP 和训练循环；billodalroy 提供多算法 notebook。

**本项目选择**：先以 patrickloeber 代码建立可追溯的原版基线，再在同一代码基础上补论文 DQN 的关键机制，最后做受控实验。这样可复用游戏规则与大部分基础训练逻辑，代价是主观察不是像素、主网络不是 CNN；这些差异必须在汇报中解释。Double DQN、Dueling DQN 和 PER 只用于理论讨论。

## 02｜游戏环境

**原论文**使用 Atari 模拟器，没有贪吃蛇规则。**参考代码**的 [game.py](https://github.com/patrickloeber/snake-ai-pytorch/blob/7ea69e6b79c59db731d8befc9ec174b075efc808/game.py) 已实现 20 像素网格、三种相对动作、随机食物、撞墙/撞身检测与 Pygame 显示。

**本项目工程设计（待审核提案）**：

| 项目 | 处理方式 |
| --- | --- |
| 沿用部分 | 保留上游移动、食物增长、碰撞、得分和默认 640×480 画面，即 32×24 格；保留相对动作直行/右转/左转 |
| 尾格规则 | 上游在弹出蛇尾之前检测碰撞，因此进入移动前的尾格会被判为自撞；初期沿用并在报告中说明，不暗中改成另一套规则 |
| 必需小改 | 将 Pygame 初始化、绘制和帧率限制移到可选显示路径；训练时可无窗口步进，演示仍能显示 |
| 随机性 | 环境使用独立的可设种子随机数流，食物从空格抽样；智能体探索另用独立随机数流 |
| 回合上限 | 将上游依蛇长变化的限制改为固定每回合 1,000 步；到上限单独标记截断，撞墙/撞身仍标记游戏终止 |
| 接口 | 在现有游戏接口上返回奖励、得分和结束原因；训练和评估共用同一套规则 |

默认棋盘及 1,000 步是待审核数值。保留上游游戏逻辑比从零开发成本低；代价是需对规则与显示做少量解耦，不能称为“原版零修改”。原版没有明确定义填满棋盘后的胜利处理，本项目若遇到这一状态应结束并记录成功，不再放置食物。

## 03｜MDP 建模

**原论文**把不可完全观察的 Atari 内部状态与像素观察区分开，并用历史处理部分可观测性。**参考代码**的 [agent.py](https://github.com/patrickloeber/snake-ai-pytorch/blob/7ea69e6b79c59db731d8befc9ec174b075efc808/agent.py) 使用 11 项局部危险、当前方向和食物方位特征；它没有提供完整蛇身作为网络输入。

**本项目建模与工程设计**：

| 要素 | 定义 |
| --- | --- |
| 游戏内部状态 s | 有序蛇身格子、朝向、食物位置、当前步数和棋盘尺寸；足以决定下一步的条件分布 |
| 智能体观察 o | 直接沿用上游 11 项特征：前/右/左危险 3 项、朝向 4 项、食物相对方位 4 项 |
| 动作 a | 直行、右转、左转 3 个相对动作；不允许一步直接掉头 |
| 转移 P | 移动和碰撞确定；吃到食物后在空格中随机放置新食物 |
| 奖励 R | 先沿用上游吃食物 +10、碰撞 −10、普通移动 0；固定步数截断的奖励提议为 −10 |
| 折扣 γ | 先沿用上游 0.9 |
| 结束 | 碰撞或填满棋盘为游戏终止；固定 1,000 步为截断，单独记录原因 |

**关键理论边界**：11 项观察不包含全部蛇身，也不包含剩余步数，因此不能声称观察本身满足马尔可夫性。课程报告应写清完整游戏状态构成 MDP、上游 DQN 实际使用的是部分观察近似。此前“有序网格观察 + CNN”的决定已由开源复用优先的选择替代。若实验显示局部观察严重限制成绩，再提出扩展观察的方案变更，而不是在主要实验中悄悄替换输入。

固定步数截断虽单独标记，但本提案把 1,000 步视为本回合可获得奖励的边界，训练目标在该边界不继续自举。这是有限时域工程选择，不是原论文定义的贪吃蛇处理；请在审核时确认。

## 04｜DQN 算法

**原论文**：从像素 CNN 输出各动作价值，使用 ε-greedy、均匀回放、独立目标网络和周期性硬同步；Atari 实验还使用 RMSProp 与 TD 误差截断。**课程课件**：主网络、目标网络、均匀回放和平方 TD 损失。**上游代码**：[model.py](https://github.com/patrickloeber/snake-ai-pytorch/blob/7ea69e6b79c59db731d8befc9ec174b075efc808/model.py) 是 11→256→3 MLP、MSE、Adam，下一状态目标仍调用同一个网络；agent.py 每步用单条新经验更新，并在回合结束后再做一次回放更新。

**本项目最小必需修改（待审核实现范围）**：

1. 保留 11→256→3 MLP、三个动作 Q 值输出、MSE 与 Adam；建立同形状的在线网络和目标网络，初始化时复制参数，每隔固定次数硬同步。
2. 经验仍存入上游容量为 100,000 的回放池；取消“每步在线单样本 + 仅回合结束回放”的混合节奏，改为热身后按统一间隔从池中均匀抽取 mini-batch。这样才便于解释论文回放机制及其消融。
3. 目标网络只计算目标，不反向传播。对终止或本项目固定回合边界的截断转移，TD 目标为当步奖励；其他转移为奖励加折扣后的下一状态目标网络最大 Q 值。只对所选动作计算平方 TD 误差。
4. 原版保留为来源清楚的对照实现；“无目标网络”和“无回放”消融从**同一改造版**分别关闭组件，避免把原版与改造版所有差异误算成目标网络效果。

| 参数 | 待审核提案 | 与上游/论文关系 |
| --- | --- | --- |
| 网络 | 上游 MLP，11→256→3 | 最大程度复用；不同于论文的像素 CNN |
| 折扣、学习率 | γ=0.9；Adam 学习率 0.001 | 沿用上游；论文实验另有配置 |
| 回放容量 | 100,000 条 | 沿用上游 |
| 热身与批次 | 先收集 1,000 条；之后 batch size 128 | 为按环境步数回放训练做的本项目调整 |
| 更新节奏 | 每 4 个环境步更新一次 | 本项目调整；所有改造版及消融组保持一致 |
| 目标网络 | 每 1,000 次优化更新硬同步 | 迁移论文机制，具体间隔待审核 |
| 探索 | ε 从 1.0 按环境步数线性降至 0.05，前 50,000 步完成，之后保持 0.05 | 替换上游按游戏次数衰减的日程，便于公平比较 |

**代码差异应明确报告**：原论文用 CNN、RMSProp 与截断 TD 误差；本项目保留上游 MLP、Adam、MSE。两者共享所要验证的回放和目标网络机制，但本项目不能称为论文的完整架构复现。

## 05｜实验设计

**原论文**报告多游戏表现、随机/人类等基线及关键组件消融。**参考代码**第一份主要绘制训练得分，缺少独立固定种子评估；第二份 notebook 的数字不能直接作为本项目结果。

**本项目实验设计（预算待审核）**：

| 组别 | 作用 |
| --- | --- |
| 上游原版 | 说明直接复用能得到什么，作为实现参考基线；结果与改造版分开解释 |
| 随机策略 | 无学习基线 |
| 简单规则策略 | 选择不碰撞且更靠近食物的动作，作为可解释基线 |
| 改造版完整 DQN | 同时有均匀回放和独立目标网络 |
| 无目标网络消融 | 使用在线网络计算目标，但保持停止目标梯度与其他训练设置 |
| 无回放消融 | 每次仅用当步新转移更新，不建回放池；保留相同环境步数和优化步数 |

正式对照的后三个训练组各用 3 个种子、每种子最多 200,000 环境步，共 9 次训练；随机/规则策略只评估。每 20,000 步在与训练分离的固定 100 个种子上评估；主要指标为每回合吃到的食物数，辅助指标为存活步数、结束原因和训练耗时。展示单个训练种子及跨种子的均值、标准差，不声称人类水平。

无回放组的 batch size 必须从 128 变为 1，报告中应注明这项混杂因素；它不是单一因素的严格因果实验。上游原版也因探索日程、更新节奏不同，不用于计算目标网络的单独增益。预算和评估数值是待审核提案，首次运行后若需调整，应对所有组别统一变更并记录理由。

## 06｜工程架构与迁移顺序

**原论文没有规定仓库结构。**第一份开源仓库现有 game.py、agent.py、model.py、helper.py、字体、README 和 LICENSE；本项目不预先拆成全新软件包。

**本项目工程设计（审核后才执行）**：

1. 在单独提交中，把用户提供的上游源码和许可按原样导入项目中的 snake_ai/ 目录，记录上游提交 7ea69e6，保留原 MIT 版权与许可声明；ZIP 不重复提交。上游 arial.ttf 的再分发权未单独核对，公开仓库先不导入该字体。用户原放入的 snake-ai-pytorch-main/ 目录保持原样。
2. 在后续小提交中修改导入副本：先把字体调用改为系统字体，并实现可选显示、种子和固定上限，再补独立目标网络与统一回放更新。每项修改均能与上游源码快照对照。
3. 仅新增必要的评估脚本、配置和 CSV/图表输出。训练、评估、演示调用同一个游戏规则实现；大权重和运行日志不直接进入 Git。
4. 只为容易出错的规则与 TD 目标做针对性检查：撞墙/撞身、上游尾格碰撞规则、食物不落在蛇身、截断原因、终止目标不自举、目标网络同步。确认后再安装依赖并做有界运行检查。
