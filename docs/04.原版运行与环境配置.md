## 本机环境

本次使用 macOS 15.8.3、Intel x86_64、Python 3.10.7，CPU 运行。直接依赖版本保存在 [requirements-upstream.txt](../requirements-upstream.txt)：PyTorch 2.2.2、NumPy 1.26.4、Pygame 2.6.1、Matplotlib 3.10.9 和 IPython 8.39.0。这是本机验证配置，其他系统还需各自确认可用的软件包。

PyTorch 版本根据本机 Intel macOS 的可用安装包选择，NumPy 保持 1.x 以兼容该 PyTorch 构建。首次启动可能需要等待动态库加载和 Matplotlib 字体缓存生成。

## 安装依赖

在 RL-Snake 项目根目录执行；已有 `.venv` 时无需重复创建：

```bash
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install --index-url https://pypi.org/simple -r requirements-upstream.txt
python -m pip check
```

本机默认镜像未找到可用的 PyTorch 安装包，改用上述官方包源后安装成功。NumPy、Matplotlib 等包均安装在项目虚拟环境中。

## 推荐启动方式：指定训练回合数

在 RL-Snake 项目根目录执行：

```bash
.venv/bin/python scripts/train_upstream.py --episodes 100
```

将 `100` 改为 `500` 或其他正整数即可调整本次运行的总回合数。一回合是从游戏重置到死亡/超时的完整过程，和网络更新次数不同。脚本默认 100 回合，达到目标后自动退出；`Ctrl+C` 或关闭游戏窗口也可停止。

这个启动脚本调用上游原版 `agent.train()`，只替换它的绘图回调，以便统计完成回合、保存曲线并在指定回合退出。游戏规则、状态特征、网络和训练更新保持上游实现。游戏窗口保留；曲线改为保存图片，不再弹出 Matplotlib 原生窗口。

每次运行生成独立的 `runs/upstream-时间戳/`，启动时会打印实际路径：

- `scores.csv`：各回合得分和累计平均分。
- `scores.png`：每回合刷新一次的得分曲线，可用系统图片查看器打开。
- `summary.json`：目标回合数、实际完成数、结束原因和用时。

如需额外限制训练循环的运行时间，例如最多 5 分钟：

```bash
.venv/bin/python scripts/train_upstream.py --episodes 100 --max-seconds 300
```

回合数或时间任一达到即结束。`--max-seconds` 目前支持 macOS/Linux，时间不包含依赖导入。原版自动保存最高纪录模型的规则保持原样，也仍不支持自动加载模型续训。

## 直接启动上游原版（本机存在绘图崩溃问题）

当前仓库已包含改造后的 `snake-ai-pytorch-main/`，组员无需再次克隆。以下命令仅供在不含该目录的工作区单独获取未修改上游版本时使用；不要在已有改造目录上执行：

```bash
git clone https://github.com/patrickloeber/snake-ai-pytorch.git snake-ai-pytorch-main
git -C snake-ai-pytorch-main checkout 7ea69e6b79c59db731d8befc9ec174b075efc808
```

在 RL-Snake 根目录执行以下两条命令启动原版：

```bash
cd snake-ai-pytorch-main
../.venv/bin/python agent.py
```

程序会打开贪吃蛇游戏窗口与训练曲线窗口，并在终端输出回合数、得分和最高纪录。原版训练使用无限循环；按 `Ctrl+C` 或关闭游戏窗口结束。当前必须先进入源码目录，因为字体 `arial.ttf` 使用相对路径加载。从根目录直接执行 `.venv/bin/python snake-ai-pytorch-main/agent.py` 会因字体路径而失败。

本机不建议继续使用上述直接启动方式：用户后续运行约 13 局后出现 `illegal hardware instruction`。原版 `agent.py` 第 110 行是 `while True`，它没有训练次数上限；该退出是进程崩溃，不是达到回合数。

本机 2026-11-13 的三个 Python 崩溃报告均指向 AppKit 的 `NSPersistentUIRequiresSecureCoding`；系统记录提示窗口状态恢复的 secure coding 初始化发生冲突，最新堆栈经过 Matplotlib 的 `_macosx` 事件循环，包含 `MatplotlibAppDelegate`。这是本机崩溃证据，不能由报错名字推断为 CPU 不支持 PyTorch 指令。

推荐启动脚本采用 `Agg` 后端写图片，避免加载 Matplotlib 的 macOS 窗口后端。[Matplotlib 官方说明](https://matplotlib.org/stable/users/explain/figure/backends.html)将 Agg 定义为非交互式文件绘图后端。

原版达到新纪录时可能在当前源码目录的 `model/model.pth` 保存权重。权重文件被项目 `.gitignore` 排除，不应视作课程正式实验的最终模型。
