## 已确认

### 01 项目定位

- **方向**：迁移并验证 DQN 关键机制，以《Human-level control through deep reinforcement learning》（Nature, 2015）为主要理论依据，将贪吃蛇作为本项目的研究任务。
- **代码基础**：优先复用 patrickloeber/snake-ai-pytorch，必要时做最小改造；billodalroy 仓库用于对照阅读。开源代码是工程基础，不能替代主论文作为算法符合性的依据。
- **课程主线**：贯通“MDP 建模 → 算法学习 → 实验效果”，形成能够解释建模、学习过程与实验证据的课程项目。
- **表述边界**：论文研究的是 Atari 游戏；贪吃蛇任务及其具体实现属于本项目设计，不称为论文原有实验或论文结果的直接复现。参考代码作为实现参考，算法是否符合论文以 PDF 正文和代码核对为准。
- **确认来源**：用户明确选择 B 方案，并要求贯通上述三环节。

### 02 游戏环境

- **方向**：以 patrickloeber 仓库的 game.py 为游戏环境基础，沿用其网格移动、三种相对动作、食物与碰撞规则；为受控实验按需增加无界面运行、固定种子和评估接口，避免从零重写环境。
- **表述边界**：这是本项目的工程设计。原论文使用 Atari 模拟器，没有定义贪吃蛇环境；两份参考代码仅供实现参考。
- **已保留的确认项**：回合采用固定总步数上限，达到上限时单独标记为截断；具体上限数值待技术方案审核。
- **尚待细化**：显示与规则的最小解耦方式、默认网格尺寸、初始化与食物随机性、上限数值及胜利条件。

### 03 MDP 建模

- **方向**：区分游戏的完整内部状态与智能体观察。完整内部状态可用有序蛇身、食物、朝向和步数表示并用于分析 MDP；主智能体优先沿用上游 11 项危险/方向/食物局部特征，采用直行、左转、右转三个相对动作。
- **已保留的确认项**：吃到食物为正奖励、碰撞为负奖励、普通移动为零；回合采用固定总步数上限并单独标记截断。
- **表述边界**：11 项观察缺少完整有序蛇身和剩余时间，不能称为完整马尔可夫状态；应在课程报告中明确它是对完整游戏状态的部分观察。原论文并未定义贪吃蛇 MDP。
- **尚待细化**：是否为 11 项观察增加步数特征、奖励数值、折扣因子、上限数值及截断时的学习目标处理。

### 04 DQN 算法

- **方向**：以上游 11→256→3 的 MLP、Adam、MSE、ε-greedy 与回放训练代码为基础，补足独立目标网络、周期性硬同步、固定目标梯度和可受控的回放更新，以验证指定论文的关键机制。
- **已保留的确认项**：课程主算法为基础 DQN；Double DQN、Dueling DQN 与优先经验回放（PER）只在理论讨论中介绍，不作为主算法或必做实验。MSE 与 Adam 保持不变。
- **表述边界**：上游原版没有独立目标网络，不能直接称为主论文的完整 DQN；本项目保留 MLP 和局部观察，也不等于论文从像素输入的 CNN 实验。原论文使用 RMSProp 并截断 TD 误差，不能与本项目的 Adam、MSE 混称。
- **尚待细化**：目标网络同步间隔、回放更新节奏、探索率、训练预算及消融实现。
- **确认来源**：用户先确认 02–04 的原推荐方案，后于 2026-11-13 明确改选“以 patrickloeber 为基础、最小改造”；当前方向以上述新选择为准。
- **课件参照**：本地 PPT/4-DQN.pdf 与 PPT/5-DQN改进.pdf 说明函数逼近、主/目标网络、均匀经验回放及 TD 更新，但没有规定网络层结构或优化器；主论文 PDF 仍为主要理论依据。

### 05 实验设计

- **方向**：采用受控基线与关键机制消融。完整 DQN 与随机策略、简单规则策略比较，并分别检验移除经验回放或独立目标网络的影响；在相同环境交互预算下，用独立于训练的随机种子评估，并报告吃到食物数量、存活步数及多次运行的差异。
- **表述边界**：这些贪吃蛇基线、指标和消融安排是本项目实验设计，不能称为论文原有贪吃蛇实验。
- **尚待细化**：随机种子数量、交互预算、评估回合数、规则策略定义和统计呈现方式。

### 06 工程架构

- **方向**：以开源仓库现有 game.py、agent.py、model.py、helper.py 的脚本边界为起点，按必要性新增配置、独立评估和实验记录，避免迁移前大规模重构；训练与评估仍应调用同一套游戏规则。
- **表述边界**：模块划分与协作流程属于本项目工程设计，原论文没有规定课程项目目录结构。
- **尚待细化**：具体目录、模块接口、配置与运行方式；在完整技术方案审核前不开始实现。
