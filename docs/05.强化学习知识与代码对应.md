# 05. 强化学习知识与代码对应

本讲解服务于课程主线：**MDP 建模 → 算法学习 → 实验效果**。依据为用户提供的课件、指定 Nature 2015 论文 PDF 和本地上游源码。此文是知识说明，不确认新的算法参数，也不修改上游算法。

## 01. 项目定位：我们学习什么

强化学习让智能体通过与环境交互学习决策。贪吃蛇中，智能体选方向，环境执行移动，返回奖励与下一次观察。动作既影响当前是否吃到食物，也影响未来能否存活、是否被蛇身困住，因此需要考虑一串动作的后果。

我们使用强化学习，是为了研究从交互中学习长期决策与 DQN 机制；不能声称贪吃蛇只能用强化学习解决。已知规则时，搜索、规划、规则策略也能发挥作用，应作为对照。监督学习需要额外的动作标签或示范数据，本项目目前只有环境反馈。

理论学习范围：MDP、部分可观测性、回报、策略、价值函数、Bellman 方程、TD、自举、Q-learning、探索、函数逼近、目标网络、经验回放与实验验证。PG、PPO、离线 RL 等可以用于算法选型比较，不必为本项目全部实现。

## 02. 游戏与交互：奖励不是得分

原版在 `game.py` 实现游戏规则，在 `agent.py` 实现决策和训练。每次交互的基本过程为：

```text
观察 o_t → 选择动作 a_t → 游戏移动 → 奖励 r_(t+1)、下一观察 o_(t+1)、结束标记
```

原版相对动作顺序为 `[直行, 右转, 左转]`，以 one-hot 数组传入游戏，例如 `[0,1,0]` 表示右转。不是绝对的上、下、左、右。

原版奖励：吃到食物 +10，普通移动 0，碰撞或超时 -10；界面 Score 则是吃到的食物数量。累计奖励、折扣回报与食物得分是不同量。报告中应分别说明训练优化的目标与最终评估指标。

“一步”指一次动作和环境转移；“一局/回合”指从重置到结束；“一次优化更新”指一次反向传播和参数更新。三者数量不相等。修改 `--episodes` 控制回合数，不直接指定梯度更新次数。

## 03. MDP：如何建模

课件 Introduction PDF 第 28–29 页把 MDP 写作 `(S,A,P,R,γ)`。有限回合任务还要说明初始状态分布与终止条件。

| 要素 | 贪吃蛇的对应 |
| --- | --- |
| 完整状态 s | 有顺序的蛇身位置、朝向、食物位置、步数；棋盘尺寸作为固定环境参数。步数影响原版超时条件，不能遗漏 |
| 观察 o | 当前网络实际收到的 11 项二值特征 |
| 动作 a | 直行、右转、左转 |
| 转移 P | 移动、增长和碰撞由规则决定；新食物位置随机生成 |
| 奖励 R | 原版 +10/0/-10 |
| 折扣 γ | 原版 0.9 |
| 初始与结束 | 固定初始蛇和朝向、随机食物；碰撞或原版超时结束 |

马尔可夫性的意思是：已知完整当前状态和动作，未来分布不再依赖更早历史。它不要求环境确定，也不表示状态只能包含“当前画面”。

`get_state()` 的 11 项输入是：前/右/左危险 3 项、当前朝向 4 项、食物相对方位 4 项。它没有完整蛇身，也没有时间。两个完整棋盘可能得到同样的 11 项观察，却需要不同的长远决策。因此严格写法是：**完整游戏状态可建模为 MDP，智能体使用部分观察近似；不能宣称 11 项观察已经满足马尔可夫性。**

这种信息丢失不能靠增加训练局数或换成更大网络自动消除。主论文也讨论部分可观测性：理论上考虑观察/动作历史，实际使用预处理后的连续帧作为有限历史表示（主论文 PDF 第 6 页）；它也没有因此证明所有游戏输入都成为完整状态。

上述贪吃蛇 MDP 和奖励是上游实现与本项目分析，不是 Nature 论文的原始任务。

## 04. 回报、策略、价值和 Q-learning

从时刻 t 开始的折扣回报写作：

`G_t = r_(t+1) + γ r_(t+2) + γ² r_(t+3) + ...`

目标是最大化期望回报。当前这一步没有奖励，也可能把蛇带到未来能吃食物的位置。γ 越小，越侧重近处奖励；原版 γ=0.9 时，10 步之后奖励的权重为 `0.9^10≈0.349`。γ 不是学习率，也不是探索概率。

策略 `π(a|s)` 描述如何选动作；状态价值 `V^π(s)` 是按策略行动时的期望回报；动作价值 `Q^π(s,a)` 则先固定执行动作 a，再按策略行动。最优动作价值 `Q*` 满足 Bellman 最优方程：

`Q*(s,a) = E[r + γ max_(a') Q*(s',a') | s,a]`

终止之后的未来回报为零。这个关系把长期问题分解成即时奖励加下一状态的价值。

表格 Q-learning 用一条真实交互更新一个表项：

```text
y = r                         （真正终止）
y = r + γ max_(a') Q(s',a')    （非终止）
δ = y - Q(s,a)
Q(s,a) ← Q(s,a) + α δ
```

`y` 是 TD 目标，`δ` 是 TD 误差，`α` 是学习率。用当前价值估计构造目标叫**自举**，因此不需要等整局结束才学。

例：当前预测 `Q(s,a)=1`，奖励 0，γ=0.9，下一状态的三个动作价值为 `[2,4,1]`，则 `y=3.6`、`δ=2.6`，更新应把当前动作的估值往 3.6 拉近。如果此步死亡、奖励 -10，则 `y=-10`，不能再加下一状态价值。

这对应 PPT 3 PDF 第 28、32–33 页与 PPT 4 PDF 第 30 页。Q-learning 的目标取下一状态最大 Q 值；SARSA 则用行为策略实际选出的下一动作。MC 通常等到完整采样回报后更新；TD 使用一步奖励和后续估值，可以更早更新。

### 探索与 off-policy

ε-greedy 以 ε 概率随机选动作，否则取最大 Q 值动作。刚初始化的网络没有可靠策略，必须探索其他动作的后果。

原版 `epsilon = 80 - n_games` 并不是标准化的概率；它与 `randint(0,200)` 比较，因此初始随机分支概率为 `80/201≈39.8%`，80 回合后为零。它不是“初始 80% 探索”。进入随机分支后仍可能恰好选到贪心动作。

Q-learning 的行为策略可以含随机探索，但学习目标始终使用下一状态的贪心最大值，因此是 **off-policy**。off-policy 不等于离线训练，也不等于“不需要探索”。原版属于在线交互、off-policy 学习。

课件 PPT 4 的 PDF 第 31 页标题写有 “On-policy Q-learning”；其最大 Q 值更新公式应结合 PPT 3 第 32 页和 PPT 5 第 18 页理解为 off-policy。边交互边更新描述的是在线采样，不改变 Q-learning 的策略分类。

## 05. 从 Q 表到 DQN：为什么需要回放和目标网络

原版使用 `11 → 256 → 3` 的 MLP 来计算 `Q_θ(o,a)`。中间层有 ReLU，虽然类名是 `Linear_QNet`，整个网络并不是单一线性函数。三个输出对应三个动作的价值，不是概率，不需要 softmax，总和也不要求为 1。

完整蛇身状态空间很大，但当前 11 个二值输入最多只有 `2^11=2048` 种组合，因此对这个观察编码而言，Q 表本身并非一定放不下。采用 MLP 的主要理由是复用开源实现、研究 DQN 的函数逼近与稳定机制；不能把神经网络说成此编码唯一可用的方案。

对一批样本，课件中的平方 TD 损失为：

```text
L(θ) = (1/B) Σ_i [Q_θ(o_i,a_i) - y_i]²
```

Adam 通过反向传播调整 θ，使已选动作的预测接近目标。反向传播是实现更新的工具；真正的强化学习区别在于目标由环境奖励和后续价值构造，而不是固定的人工动作标签。

神经网络会共享参数，更新一个样本可能改变许多观察的预测；相邻游戏经验相关，目标又依赖价值估计。这些因素使训练可能振荡，不能把表格 Q-learning 的收敛结论直接套到神经网络上。

### 均匀经验回放

把 `(o,a,r,o',done)` 存入回放池，更新时均匀随机抽 mini-batch，既减弱相邻经验的时间相关性，又重复使用交互数据。均匀针对“已存储的经验”，不代表所有状态动作都被均匀访问，也不保证样本完全独立。

原版已有容量 100,000 的 `deque` 和随机采样，但其节奏是：每步对新经验更新一次；回合结束后再从池中做一次更新。函数名 `train_long_memory()` 表示使用历史经验，并不是计算整局回报，也不是多步 TD 或 MC。

### 独立目标网络

基础 DQN 维护在线网络 θ 与目标网络 θ⁻：

```text
y = r                                      （真正终止）
y = r + γ max_(a') Q_(θ⁻)(o',a')            （非终止）
每次优化只更新 θ；每隔 C 次约定的更新，复制 θ⁻ ← θ。
```

目标网络让参考值在一段时间内保持稳定，减轻“预测值变化时目标也同时跟着变”的问题。TD 目标必须被视为常数，不反向传播，通常用 `torch.no_grad()` 计算；硬同步和停止目标梯度是两件需要分别实现的事。

原版 `model.py` 只有同一个网络用于当前预测和下一状态估计；`pred.clone()` 复制张量却不切断计算图。因此它不等于课件中具有独立目标网络、固定目标梯度的完整基础 DQN。

主论文 PDF 第 7 页与 PPT 5 PDF 第 5–18 页是上述机制的依据。主论文还有像素预处理、CNN、RMSProp、奖励裁剪与更新误差截断；本项目保留局部观察、MLP、Adam 和 MSE 是已讨论的适配，不能称为论文全部实现的直接复现。

Double DQN、Dueling、PER 是课件后半部分的后续改进。主线只实现基础 DQN，改进方法用于讨论，不能混写为指定主论文已经采用的方法。

## 06. 工程实现：公式应落在哪里

| 知识 | 原版入口 | 后续需要处理的内容 |
| --- | --- | --- |
| 环境转移与奖励 | `game.py: play_step()` | 固定种子、结束原因；环境规则变更须明确记录 |
| 部分观察 | `agent.py: get_state()` | 保留 11 项输入并说明局限；不悄悄换成完整状态 |
| 探索策略 | `agent.py: get_action()` | 可配置探索日程，避免误解原版 epsilon 的量纲 |
| 回放 | `remember()`、`train_long_memory()` | 统一采样更新节奏，便于公平消融 |
| Q 值与损失 | `model.py: Linear_QNet`、`QTrainer` | 增加目标网络、停止目标梯度；明确只对所选动作算损失 |
| 次数、曲线与运行兼容 | `scripts/train_upstream.py` | 现有启动包装只管理回合数和显示，不会自动补齐算法机制 |

终止和截断要特别区分：碰撞属于任务终止，目标为即时奖励；外部运行时间限制通常只是停止采样，不意味着未来价值为零。如果把固定回合时限定义为任务本身的奖励边界，则是有限时域任务，应把剩余时间纳入建模，并在边界停止自举。采用哪种含义需要在代码、报告和评估中保持一致；目前具体处理仍待技术方案审核。

## 07. 实验效果：怎样证明改动有用

游戏能运行说明功能链路可执行；得分偶尔变高还不足以证明算法改善。课程实验需要回答：学到的策略是否优于基线，回放和目标网络各起什么作用，结果是否稳定。

| 对照 | 要回答的问题 |
| --- | --- |
| 随机策略 | 学习是否优于没有学习的动作选择 |
| 简单规则策略 | 学习相对已知规则有什么价值或局限 |
| 上游原版 | 直接复用开源教学代码有什么表现 |
| 同一改造版的完整 DQN/去目标网络/去回放 | 关键机制移除后，成绩、方差与稳定性如何变化 |

不能把原版与改造版之间所有差异都算作目标网络收益。消融组应尽量固定输入、奖励、环境、交互预算、探索日程和其他参数。没有回放时批量训练形式可能变化，应说明混杂因素，不夸大因果结论。

正式比较优先控制总环境步数：强策略每局活得更久，相同局数不等于相同交互成本。评估应与训练分开，不更新参数，明确评估探索率，使用独立的食物随机流。多组训练种子用于观察训练随机性；多组评估种子用于观察测试局面差异，两者不能互相替代。

主要报告每回合食物数的均值与离散程度，辅以存活步数、结束原因和耗时。最高纪录用于观察个例，不能替代均值；存活长也可能只是绕圈；TD loss 小也可能是对错误或不充分目标拟合得好，不保证策略更强。

奖励设计、局部观察、有限算力和棋盘规则都属于需要汇报的局限。具体训练种子数、预算和超参数仍以技术方案审核结果为准。
